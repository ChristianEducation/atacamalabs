## F3 · Decisiones humanas (27-oct-2026)
**Workflow 29 (`scripts/ops/ops-actions-core.mjs`, `n8n/build/ops-actions.mjs`, JSON regenerado):** lista cerrada +2 acciones: `strategic_decide {opportunity_id, decision: shortlist|work|dismiss, reason?, expected_status?}` y `strategic_target_confirm {target_id, repo_full_name, deployment_url, health_url, provider?, reason}`. - Cada una: sesión PIN + `X-Ops-Approval` (ya existentes), `request_id` único, lectura de la fila fresca, **un solo PATCH condicional** `…&status=eq.<anterior>&is_test=eq.<…>` con `Prefer: return=representation` y revisión de fila afectada; auditoría en `operator_audit_log` (nivel 2; la confirmación de servicio nivel 3). Cero llamadas externas: ni Ingest, ni GHL, ni correo.
- Transiciones: `new → shortlisted|working|dismissed`, `shortlisted → working|dismissed`, `working → dismissed`; `dismissed`/`expired` son terminales (`estado_terminal`).
- **`stale_state`:** si `expected_status` (lo que Christian veía) no coincide con la fila, o si el PATCH no cambia filas (carrera), responde `error:'stale_state'` con «Este registro cambió. Recarga para decidir sobre la última versión.» y no escribe. `RESPOND` ahora usa `check_error` de cada escritura (antes siempre `sin_cambios`; el resto de acciones no cambia).
- **Idempotencia:** mismo `request_id` → devuelve el primer resultado (`replayed:true`, 0 escrituras); otro clic con otro `request_id` cuando ya está en ese estado → `already_<estado>` sin mutar.
- `is_test`: una acción real no toca un registro de prueba y una prueba no toca uno real.
- `strategic_target_confirm`: solo `candidate → confirmed`, deja `monitor_enabled=false`, no toca `strategic_radar_config`; rechaza http, localhost, IP privada/metadatos, usuario/clave, puerto ≠ 443, tokens en la URL, hosts sin dominio, data URL, repo mal formado, razón < 8, proveedor con basura. Ya confirmado: idempotente si coincide, error si difiere.
- Las decisiones se anotan aunque la pausa general esté activa (no producen efectos externos; spec §17.4).
- **Decisiones mías:** (1) `expected_status` es un campo opcional que agregué al contrato del spec (la UI lo envía) para detectar «versión vieja» de verdad; sin él, solo cuenta la carrera. (2) La validación de la URL es solo de FORMA (n8n no resuelve DNS): el SSRF/redirecciones se revisan en cada chequeo del monitor (F4), no aquí.
